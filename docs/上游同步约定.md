# Fork 与上游同步约定

## 仓库与分支

上游：[xiaoyang111222/cn-math-taxonomy](https://github.com/xiaoyang111222/cn-math-taxonomy)。苏教版：[lvshin/cn-math-taxonomy · suzhou-primary](https://github.com/lvshin/cn-math-taxonomy/tree/suzhou-primary)。

| 分支或远程 | 职责 |
|---|---|
| `upstream` | 原作者仓库，获取上游更新 |
| `origin` | 苏教版Fork，保存改编成果 |
| Fork 的 `main` | 采用快进同步，跟随上游 |
| `suzhou-primary` | 苏教版长期维护 |
| 临时同步分支 | 在独立工作副本中适配、解决冲突和验证 |

当前采用的上游基线为 `10a0f562b32433b785729661c2164756cb933154`。基线推进只代表实际采用的内容；检查SHA、采用的提交与跳过的提交分别记录。

## 同步时机

- 判题、诊断或运行正确性的适用修复优先处理。
- 有价值的通用功能与数据修正结合维护阶段批量引入。
- 大规模界面、数据结构或概念ID调整先核对映射、题库和记录兼容性。
- 其他教材版本或未采用功能的变化可以暂不引入，保留判断依据。

## 同步流程

1. 核对干净工作区、远程与采用基线，列明适用、跳过和待适配内容。
2. 在独立副本准备变更，按需要合并、挑选提交或适配，保留来源SHA。正常维护不强制推送，不丢弃其他人的改动。
3. 维护苏教目录、落位、题目覆盖与证据质量；更新实际采用的上游快照，通过配置构建数据，不能直接用其他教材册次覆盖苏教落位。
4. 保持稳定ID；数据和题目变化提升 `data_version`，核对旧记录兼容性。
5. 运行 README 的必要检查；界面或部署适配变化补充对应验证。
6. 同时检查当前公开文件、图片、提交消息和待推送历史中的个人部署信息。个人域名、设备与服务映射、本机路径、私有导航及截图保存在仓库之外；不能因用户授权推送程序而一并公开个人环境。
7. 验证后提交并推送适用分支，再按本机私有部署约定交付。公开记录只保存通用实现与验证结论。

参考：[GitHub 官方：同步 Fork](https://docs.github.com/en/pull-requests/collaborating-with-pull-requests/working-with-forks/syncing-a-fork)。

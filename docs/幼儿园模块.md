# 幼儿园亲子活动

幼儿园入口为 `/edu/kindergarten/`，小学数学入口保持 `/edu/math/`。两者使用同一家庭、孩子档案与统一登录，由成人选择活动、在线下陪伴并记录过程。幼儿园活动不进入小学练习画像，也不计算素质分数或排名。

## 首批内容

独立内容版本 `2026-10-22-preschool-v1`，16张活动卡，8个主题各2张：表达沟通、情绪、关系修复与协商、规则轮流与公平、生活自理、运动与安全、想象创造、变化与新体验。

活动卡连接布鲁伊相关游戏与可确认的剧集，包含材料、场地、参与方式、步骤、家长提示、观察方向、简化/变化玩法与安全提醒。家庭玩法单独标为“家庭活动改编”，不冒充原作规则；游戏中文名是工作译名，剧集中文名标注TMDB zh-CN来源。没有确认对应动画的活动保留待确认，不根据同名标题猜测关联。

内容为重新编写的通用活动，未包含原始私人笔记、个性化话术或孩子反馈。活动可以直接开展，观看动画为可选；应用不托管动画视频、剧照或完整脚本。来源及原有名称的权利归原权利人，资料核对状态不表示幼教专家审定。

## 资料维护

通用源文件为 `config/preschool.json`，运行：

```sh
python3 scripts/build_preschool.py
python3 -m unittest discover -s tests -p test_preschool_catalog.py
node tests/test_preschool_ui.js
```

生成 `data/preschool.json`，不依赖私人知识库或网络。小学课程数据、原有题目和变式模板版本不随幼儿园内容更新。活动ID稳定；修改内容后提升该卡版本，历史仍读取服务端保存的旧快照。

## 登录与记录

复用 `/edu/math/api/v1/` 下的身份、家庭和孩子接口。幼儿园页面发起登录使用固定的 `module=preschool` 标识，完成后返回幼儿园入口；不接受任意返回网址。授权请求按state绑定会话内的有限记录，避免多个标签页互相覆盖返回目标。

| 接口 | 用途 |
|---|---|
| `GET /preschool/activities` | 登录后读取通用幼儿园活动；匿名浏览读取静态目录 `data/preschool.json` |
| `GET/POST /families/{family}/children/{child}/preschool/observations` | 当前孩子的幼儿园活动记录 |
| `GET /families/{family}/children/{child}/preschool/history` | 分页读取幼儿园活动历史 |

业务接口要求登录与家庭成员授权，写入校验CSRF。OWNER/EDITOR/VIEWER及归档孩子规则沿用现有权限。活动记录使用现有观察表，服务端从受信活动目录保存完整快照及 `module: PRESCHOOL`；旧数学快照缺少模块字段时按MATH处理，保持旧记录内容与幂等指纹。

模块过滤在服务端SQL执行。数学历史只含数学观察、数学练习和旧数学导入；幼儿园历史只含幼儿园观察。新增游标绑定模块，更正必须关联同一模块、同一家庭、同一孩子的既有记录，并沿用当时活动快照。重复保存不产生重复记录。

开始记录时固定家庭和孩子；切换档案不改变已有草稿归属。断网或未确认保存时保留本页草稿，重试沿用原ID，也可导出待保存内容；未收到成功确认不能视为已经同步。观察与参与方式不作为“已掌握”的推断证据。

尚未到达服务端的草稿只保存在当前页内存，导出不等于自动导入恢复；关闭页面前应保存或导出。后续活动换版若不再提供该旧版本，未提交的旧草稿可能需要重新选择活动；已保存记录的回看、更正和成功入库但响应丢失的原请求重试仍使用原快照。

## 部署边界

幼儿园静态资源随现有后端打包，内部路径为 `/edu/math/kindergarten/`，部署时将独立入口的固定HTML和资源路径代理到该目录。接口与登录仍使用已有数学应用上下文，不扩大Cookie作用域、不重建身份客户端、不修改业务库结构。

反向代理仍须拒绝内部注册路径，清理不可信转发头，保留CSRF、Secure/HttpOnly会话Cookie及既有家庭数据库RLS策略。实际域名、连接信息和私有部署配置保存在源码之外。
